# Post-MVP backlog — Life RPG

Список несостыковок и ограничений, найденных после завершения этапа 6.

**Статус:** базовый post-MVP закрыт. Следующий продуктовый этап — контент, onboarding и
ежедневный рабочий цикл; затем недельный review и напоминания.

Приоритеты:

- **P0** — влияет на корректность данных, прогресса или production-эксплуатацию;
- **P1** — заметный функциональный пробел или расхождение со `SPEC.md`;
- **P2** — UX, документация и технический долг.

## P0 — следующий проход корректности — ✅ выполнено

- [x] Определить и защитить правила выполнения задач по датам. Сейчас будущую задачу можно
      завершить заранее: XP записывается на будущую локальную дату, попадает в итог периода,
      но не отображается в графике до наступления даты. Минимум — запретить это на сервере и
      ограничить статистические запросы текущей датой.
- [x] Определить политику выполнения задним числом: разрешённый период, влияние на серию и
      отображение в истории. Нельзя оставлять неявную возможность ретроспективно менять серии
      и дневной прогресс без понятного правила.
- [x] Добавить отмену завершения квеста по модели отмены задачи: подтверждение, возврат квеста
      в активные, компенсирующая XP-транзакция и идемпотентность. Уже открытые достижения по
      текущей политике остаются полученными.
- [x] Перестать терять длительность повторяющегося действия. Поле `estimatedMinutes` есть в
      общей форме, но при выборе повторения не сохраняется в шаблон и будущие задачи. Добавить
      поле в схему шаблона, API, редактирование, материализацию, экспорт и контент-пак.

## P1 — активация, баланс и готовый контент

Реализовывать первым: механики уже готовы, но новый пользователь получает набор навыков без
готового рабочего цикла и вынужден собирать систему вручную.

### Баланс контента

- [ ] Описать единую шкалу XP для задач, повторений и квестов. Учесть длительность, усилие,
      дискомфорт и ценность результата; зафиксировать рекомендуемые диапазоны и примеры,
      чтобы ручной и сгенерированный контент не ломал баланс.
- [ ] Подготовить стартовый контент по шести характеристикам: навыки, ежедневные и недельные
      повторения, разовые задания и первые квесты. Не импортировать весь набор одному
      пользователю автоматически.
- [ ] Подготовить библиотеку шаблонов квестов по направлениям: здоровье, обучение, работа,
      финансы, отношения и личные проекты. Каждый шаблон должен иметь понятные шаги,
      длительность, награду и переносимый дедлайн.
- [ ] Добавить автоматическую проверку встроенных пакетов: схема v2, уникальность ключей и
      названий, существующие характеристики, корректные зависимости и допустимый XP.

### Первый запуск и библиотека пакетов

- [ ] Заменить автоматическую выдачу всех восьми стартовых навыков мягким первым запуском.
      Пользователь выбирает 2–3 направления и получает только подходящие навыки и контент.
- [ ] Сделать короткий onboarding без обязательного тура по интерфейсу: выбор направлений →
      предпросмотр содержимого → подтверждение → готовый экран «Сегодня».
- [ ] Переиспользовать существующий preview/commit контент-пака, чтобы onboarding не создавал
      второй независимый механизм импорта и сохранял атомарность зависимых записей.
- [ ] Добавить встроенную библиотеку контент-паков с названием, описанием, версией, составом,
      фильтром по направлению и предпросмотром вместо обязательной загрузки JSON-файла.
- [ ] Разрешить устанавливать дополнительные пакеты после onboarding и явно показывать,

## P2 — точный и полезный недельный review

- [ ] Зафиксировать определение пропущенного действия. Сейчас обзор считает только pending

- [ ] Зафиксировать определение зависшего квеста. Сейчас в обзор попадают только активные

- [ ] Показывать настоящее изменение серии за неделю относительно её состояния на начало

- [ ] Добавить сравнение с предыдущей календарной неделей: XP, выполненные, пропущенные,
      завершённые квесты и активные серии. Не превращать сравнение в оценку пользователя.
- [ ] Выделять повторения с частыми пропусками и давать действия: изменить расписание,
      уменьшить частоту или поставить шаблон на паузу.
- [ ] Позволить разобрать пропущенные задачи и зависшие квесты прямо из недельного обзора.
- [ ] Добавить выбор фокуса следующей недели и возможность создать задачу, повторение или

- [x] Разделить liveness и readiness. `/api/health` возвращает `ok` без проверки БД,

## Идеи после стабилизации основного цикла

Не реализовывать без отдельного запроса.

- [ ] Рассмотреть главы жизни и боссов только после появления готового контента и устойчивого
      ежедневного цикла. Босс должен собираться из реальных задач/шагов, а не быть отдельной
      декоративной шкалой.
- [ ] Рассмотреть титулы и перки за достижения только при наличии понятного практического
      эффекта; не добавлять отдельную валюту и магазин без самостоятельного продуктового смысла.
- [ ] Рассмотреть AI-предложения задач и квестов после накопления качественных шаблонов и
      формализации XP. Любое предложение должно проходить предпросмотр до записи.
- [ ] Рассмотреть интеграции Health, календаря и финансов как отдельные импортные адаптеры,
      не связывая внешние источники напрямую с начислением XP без подтверждения пользователя.
